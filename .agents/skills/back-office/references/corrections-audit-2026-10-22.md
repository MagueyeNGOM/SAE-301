## Complément du 22/10/2026 — nouvelle mesure directe et netteté du bandeau
Le HTML public sert bien la nouvelle build (fichier JS index-BcGuhSBE.js, CSS intégré), donc le transfert n'explique pas les scores. Lighthouse Chrome sur l'URL publique mesure 80/100 (capture utilisateur : 75, mêmes trois catégories à 100). FCP 2,325 ms, LCP 4,245 ms, TBT 29 ms. Le rapport compte du HTTP/1.1 et des ressources script/CSS à URL opaques sur l'origine, absentes de la réponse HTML brute ; il leur attribue jusqu'à 900 ms de blocage du rendu et 1,290 ms d'économie potentielle avec HTTP moderne. Origine de ces injections non identifiée ; le mode de transport relève de la configuration du serveur, non de .htaccess. Ces facteurs empêchent de garantir 99 par du code front seul.
Cause certaine du bandeau flou : le visuel source est 3 200 x 1 200 px mais l'image de fond occupe 412 x 420 CSS px sur mobile. Le navigateur avait choisi le dérivé 960 x 360, agrandi en hauteur. Correctif : images spécifiques `bandeau-accueil.png` WebP qualité 85 ; source preload et `sizes=1200px` cohérents avec un dérivé 1280 x 480. Taille produite ~110 Ko contre ~83 Ko pour la variante 1280 précédente, encore bien sous l'original 889 Ko. `npm run build` et `quality-regressions.mjs` (19 requêtes/assertions) passent. Cette dernière variante doit encore être transférée et la nouvelle mesure Lighthouse effectuée sur le site public.
